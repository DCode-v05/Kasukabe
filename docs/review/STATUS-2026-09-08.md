This document is generated the same way any future one should be: for every
finding id in the nineteen review documents, grep the **source tree** (not
the docs) for a citation of that id, and split the result three ways —
cited in production source, cited only by a test, cited nowhere. A citation
is not proof a fix works; it is proof somebody went to the code and left
their reasoning at the site. Everything claimed below that goes further
than that says how it was checked.

### Programmatic tool calling, built

Added 2026-09-09, against `docs/runs/WIRING-AND-TOOL-CALLING-AUDIT.md`
section 7, which scoped this and did not build it. The audit's
recommended order was **(3) the parent link first, then (1) with a hard
cap; (2) is done**, and that is the order it was done in. Numbered
separately from the review findings, like the TRADE items above.

| Finding | What was built |
|---|---|
| **PROG-01** | The parent link. Every step of a composite already landed in `tool_invocations` and nothing said they were one act, so the only figure that justifies the feature — acts bought per model call — was not derivable from the world's own record. `program_id` / `program_step` on the record, the trace table, the `/world/tool_invocations` route and the report. The wrapper is step 0, so a program is one `group by` and the answer is a subtraction. |
| **PROG-02** | The bounded expression layer. `when` (one comparison from a closed set), `repeat` (clamped), `bind` (a name a later step reads back as `@name` / `@name.field`), in `world/tools/program.py`. **A condition can only see what a step already paid to find out** — there is no way to read the world from inside one, because that would be a second way to read the town with no gate, no price and no record, and the whole argument that a composite is safe is that it adds no path the registry already owns. Four ceilings, all operator-settable, all enforced by the runtime: 12 steps filed, 20 repeats per step, 40 dispatches per program, 50% of the caller's opening wallet. |
| **PROG-03** | The measurement, wired to three consumers on the day it was written — `world/evals/programs.py`, a **What one decision bought** section in the run report, and `eval_metrics` rows. WIRE-02 needed three for the same reason: a fix that reaches nobody is indistinguishable from no fix. P3 (the ceilings held) is the only gate; P1 (acts per decision) and P4 (do program writers end richer) are reported and deliberately never scored. |

**The cost model is not decided here.** The audit reserves it for the
operator — *"'thinking costs money' IS the experiment ... either the most
interesting result this project could produce, or a confound that makes
every earlier run incomparable"* — and
`docs/decisions/PROG-COST-MODEL.md` sets out three arms with the lever
(`KASUKABE_PROGRAM_MAX_CALLS`) and an unfilled decision block. Setting it
to `1` keeps run 26 comparable with every run before it and leaves the
mechanism in place.

**Two defects found while building it**, both of the shape this register
already tracks:

- The `toolify` row in `action_costs.SCHEDULE_TABLE` still said calling a
  composed tool *"is priced as an unknown verb, which costs more than its
  steps did"*. TOOL-29 wrote that when the surcharge existed; TOOL-06
  then removed the surcharge and the sentence stayed. Cost disclosure
  appends that row verbatim to the served blurb, so every resident
  deciding whether to compose anything was reading that composing makes
  the work dearer — the town arguing against a feature it has, in the one
  place a resident looks before using it. The guard that should have
  caught it, `_promises_no_surcharge`, searched for `costs \d+ sim more
  than its steps` and could not see the digitless spelling. Both fixed;
  the predicate now fails on either.
- A repeated READ inside a program is folded by TRADE-04, is not charged,
  and — because `dispatch` returns before it appends — leaves no row in
  the invocation log. Counting it as an act would have put the wrapper's
  own `calls_made` permanently ahead of the rows a report can see, which
  is the two-numbers-that-disagree shape that produced the price table and
  the unread wire counters. Counted separately as `repeats_folded`; the
  ceiling is enforced against dispatches, the economics are reported
  against acts.

- **`describe_primitives` quoted a price the town does not charge.** The
  listing a resident reads before composing anything priced an invented
  tool at 5 sim, because an invented name has no row in
  `SCHEDULE_TABLE` and `cost_for` falls to `DEFAULT_RULE` - while
  `dispatch` charges nothing for the wrapper. Measured: quoted 5,
  charged 1. That is the THIRD reader of the same fact found disagreeing
  with it in this one area (the blurb, the disclosure row, the quote),
  and it is the one that argues hardest against composing, because it is
  a number rather than a sentence. Now quoted as the sum of the steps,
  at the caller's own proficiency, and guarded by measuring the quote
  against the charge rather than against a constant.

**`test_no_silent_defaults` fired again**, on a three-argument `getattr`
in the trace writer for a field `ToolInvocationRecord` declares. Removed
rather than the budget raised, which is now the fourth time.

**A ceiling that cannot be read now fails at boot.** The four operator
knobs used to fall back to their defaults on an unparseable value, which
answers a typo in a safety ceiling with the permissive number -
`KASUKABE_PROGRAM_WALLET_SHARE_PERCENT=5O` becoming 50%. Loud, at boot,
naming the variable. `0` is valid and is the strictest setting.

**Known gap, stated rather than assumed.** `describe_primitives` lists an
invented tool's name, description, parameters and price and not its
steps, so a resident can call somebody else's program and cannot learn
from it. That is a diffusion gap (T5, already 1 by construction), not a
programmatic-calling one, and serving every step of every invented tool
is a payload decision ENG-03 already cut once.

### Evaluations: the L1 gap, half closed with replays

`EVAL-08` made the coverage gap a number the suite prints, and refused to
fill it, for a reason worth quoting because it is the reason this entry
is careful:

> This does not invent the missing scenarios. A scenario is a research
> artifact: it puts a resident in the situation a verb exists for, with a
> threshold fixed before anything is measured, and one written from a
> situation nobody has ever been in is a guess about the town dressed as
> a measurement.

That constraint held while nobody had watched a town for a full game-day.
Run 25's report is 8,086 lines and carries every resident's transcript,
so twenty-eight of those situations are no longer hypothetical — they
were observed, and each new scenario cites the tick it replays.

**52 scenarios → 84. Verbs with any scenario at all: 23 of 94 → 50 of 94.**

The ones worth naming:

- **`hire_employee`** — Marta and Tova negotiated a wage aloud and Tova
  said *"I agree. Fifteen a day, six days, paid weekly."* The verb refused
  six times and **no wage was paid in the entire run**. This is the run's
  largest behavioural failure and it had no scenario. `e87762e` then found
  why it refused — `employee_consent` was defaulted rather than required,
  so TRADE-02's index row (which carries only the required names) dropped
  the one parameter deciding the call, and Marta could not have set it.
  With that fixed the scenario scores `employee_consent: true` rather than
  bare reach: reaching for the verb without it is a call that still
  refuses, and counting it would measure eagerness where the run needs an
  employee.
- **`transfer_tile`** — Nell confessed to moving a boundary marker forty
  years ago and offered Wren the land or its value. **Not one tool call
  touched it.** The situation is fully observed and the verb was never
  reached for; those are different findings and nothing could tell them
  apart.
- **`declare_candidacy`** — at `town_hall`, which is where TOOL-08's other
  half lived: the town could vote and could not stand, and every empty
  ballot in 24 runs was read as apathy.
- **`steal`** — a negative, and the only one in this batch whose evidence
  is a resident's own reasoning: Tova, short of her household share and
  unfed, wrote *"Ask for loans? Steal? No. That is not who I am."* A town
  where hunger produces theft on day one is not measuring restraint.
- **`pay_tax`** — a negative built from a real refusal ("you owe no head
  tax"), which two residents hit by reaching for a bill nobody had raised.

**44 verbs still have none**, and they are the ones nobody has been in the
situation for: `approve_patent`, `arrest`, `revive`, `auction_land`,
`table_amendment` and the rest of the governance and justice vocabulary. A
scenario for those would be exactly the guess EVAL-08 refuses to make, and
the number stays printed until a run produces the situation.

One check worth having: nothing writes a scenario folder for a verb the
registry does not have. A directory named for a tool that does not exist
is EVAL-01 in the evaluation harness itself — a measurement keyed to a
name nothing serves — and it would score zero forever while reading as
coverage.
