Round 2: the complete plan

Nine tracks, what each one actually changes, the order they have to happen in, and how to run the thing locally while you build it. The base is live: one command stands a town up and tells you what it recorded.

Date 2026-08-18 Owners me, Sharan Base rung 1 green, 1690 tests passing Companion round-2-brief.html

01 The local base

This is the loop everything else is built inside. One command generates a population, runs the town, and reads the trace back. 

# once, from a fresh clone: the Ville tilemap is a vendored checkout and
# is gitignored, so it has to be fetched. A full clone fails on Windows.
git clone --depth 1 https://github.com/joonspk-research/generative_agents.git smallville
cd smallville
git -c core.longpaths=true sparse-checkout set --no-cone \
    environment/frontend_server/static_dirs/assets
git -c core.longpaths=true checkout

# then, from app/ - the ladder, locally
make rung1        # 10 agents, 2 game-days, mock inference, no spend
make rung2        # 50 agents, 5 game-days
make local-live   # real Bedrock through the broker on :8200
make test         # or: docker compose run --rm test

# the make targets shell out to `uv run`, matching the Makefile's existing
# targets. On a machine without make or uv (a Windows dev box), call the
# script directly - it is the same code path, uv only resolves the venv:
python scripts/local_run.py --population 10 --game-days 2
python scripts/local_run.py --population 50 --game-days 5
python scripts/local_run.py --population 10 --game-days 1 --live

scripts/local_run.py is a wrapper, not a second runner. It shells out to python -m world.run_genesis with the same flags start-genesis.sh uses in production, because a regression harness that exercises a different code path from production is worse than no harness. What it adds is the three things around the run: generating the population, pointing the trace store at a real file before any child process imports the client, and reading that file back.

The trace report is the part that matters. Round 1's central finding was that two of sixteen tables had rows and nobody noticed for eight game-days. So every run prints every table, including the zeroes, with the reason attached: 

[3/3] trace report
  ledger invariant declared at 52000 cents

  agents                0   <- TraceStore not mounted by the embedded harness (RC-3, fixed by T3)
  events                0   <- TraceStore not mounted by the embedded harness (RC-3, fixed by T3)
  utterances            0   <- no speech tool exists yet (RC-2, fixed by T2)
  skills                0   <- no skill artifact is distilled yet (fixed by T4)
  llm_calls             0   <- written by the broker, which mock mode never calls
  world_snapshots       3

  world snapshots:
    tick=144   agents=10   wallets=1926   treasury=50000   burned=74    total=52000
    tick=288   agents=10   wallets=1852   treasury=50000   burned=148   total=52000

Read that as a progress bar. Every zero above is a track in this plan, and the job of Round 2 is to turn them into numbers. When utterances stops being zero, T2 landed. When agents and events stop being zero, T3 landed. A run that records nothing now exits non-zero instead of looking green.

What the base already guarantees
  • Populations from 6 upward generate, and the 250-agent output is byte-identical to the one round 1 ran on.
  • The ledger invariant is declared per run and enforced by database triggers, so a 10-agent town checks against its own 52,000 cents rather than a hardcoded $1000.
  • A failed trace write raises TraceWriteFailed and halts the run.
  • Checkpoints round-trip, and the runner boots on Windows as well as Linux.
  • 1690 tests pass, 7 skip. The 7 are the same real-hardware and live-Postgres skips STATUS.md recorded.

02 The shape of the work

Two tracks are roots and everything else hangs off them. T1 gives an agent an identity, and until it lands every behavioural gate in the round is unmeasurable, because a model with an empty system prompt is not a character failing to socialise, it is an orchestrator doing its job. T3 puts the real world server on the wire, and until it lands nothing an agent does is written down.

They are independent of each other, which is the single most useful fact in this plan: two people can start at the same time on the two things that unblock everything.

03 The nine tracks

T1 Character layering Now
Owner meFixes RC-1Depends on nothing

Round 1's agents ran with no system prompt at all. engine/src/sim/pinned_boot.py constructs Coordinator(...) with no consciousness_mgr, and the only place one is ever built is engine/src/bootstrap.py:636, the production boot path pinned_boot deliberately bypasses. So sys_prompt stayed None for every turn of every agent, and the persona was never on the wire.

Build one in the seam and layer the character across its section stabilities:

  • STABLE, cached globally: name, age, sex, household, occupation, the persona block from genesis.json, and the law of the town from build_soul_seed() — which has zero production call sites today, only its own test.
  • DYNAMIC, per session: the evolved soul from Soul.get_evolved_soul() and the agent's own social graph, so opinions about named neighbours arrive as things it knows rather than things it is told each turn.
  • VOLATILE, recomputed every turn: energy, money, burn rate, today's upkeep and tax, dependents, and what the next action costs, from app/world/tools/cost_disclosure.py — 28KB of finished code that nothing imports.

Then wire the learning centre's write_social_updates() and update_evolved_soul() so the layers actually move. A character that cannot change is a costume.

Gate

In 500 sampled turns, zero contain orchestration JSON, sub-agent charters, or the word "NPC". An agent asked who it is answers with its name. Compounding quantity 4 is met: one evolved soul diverges from its genesis persona traceably to a specific event.

T3 One world, one contract, institutions as tools Now
Owner SharanFixes RC-3, STATUS.md risk 2Depends on nothing

Four contract surfaces exist and no two of them match. The engine speaks GET /tools/registry and POST /agents/{id}/tool_calls; the embedded harness serves those plus ledger and admin; the real world server serves POST /tools/{tool_name} plus governance, social, crime, map and /ws/events, and cannot host an engine at all; the console calls twenty-odd /admin/* routes nobody serves. Round 1 ran the embedded harness, which mounts no TraceStore, which is the entire explanation for two of sixteen tables having rows.

  • Collapse onto world/main.py as the only world server: add the engine's two routes and the console's /admin/* surface. Demote build_embedded_world_app to a test fixture.
  • Every run mounts the real TraceStore and a real MapService, so move produces walked routes instead of instant jumps.
  • Give every institution a complete tool surface, so nothing an institution does can happen off the registry: government (convene, amend, vote, tax, jobs, permits, tenders, appoint police, petition); elections (declare, campaign, vote in person, concede, take office, with the government namespace transferring atomically); courts and police (complain, open a case, interview, warrant, subpoena, testify, rule, fine, jail, release, arrest); temple (ordain, rite, marry, donate, pray); business (register, hire, fire, set and pay a wage, grant and revoke tool access, sell, bequeath).
Gate

A rung-1 run through world/main.py writes rows to agents, events, utterances, transactions, memories, relationships and skills; the console drives a live world; move produces walked routes on the real tilemap; every institutional action above is callable and gate-checked, with no institutional path reachable except through the registry.

T2 Agent-to-agent speech Next
Owner SharanFixes RC-2Gate needs T3

Thirty primitives are registered and none of them is say, tell, ask or any other act of speech. DESIGN.md states that negotiation is conversation and settlement is tool calls, but conversation was never made physics, so every mechanic requiring two agents to agree was unreachable: price discovery, wage bargaining, hiring, marriage, teaching, campaigning, preaching, conspiring, testifying.

  • say addresses everyone at the location. tell addresses one named co-located agent, and others present may overhear at reduced fidelity, because that is what a whispered aside is and because who overheard what is exactly the data gossip research needs.
  • Delivery uses the substrate that already exists and has never carried anything: world/core/perception.py's hearing_window_ticks and heard_events, which already distinguish what an agent heard at its own location from what reached it from elsewhere. No listen tool is required.
  • Speech costs energy like any other action, so talking is a real economic choice. Group conversation emerges from repeated say in one place rather than from a conversation object — threading, turn-taking and interruption are behaviours to be measured, not mechanics to be imposed.
Gate

Two agents negotiate a price in language and settle it with buy and sell at the agreed number. A group of five in one place hold an exchange in which at least one aside is overheard by a non-addressee. Both fully reconstructible from the trace alone.

Watch

Conversation storms are the obvious failure mode and a live cost risk the moment this lands. Rung 1 catches it at a dollar a day, which is the entire reason rung 1 was built first.

T4 Learning: make the world the corrector Next
Owner meFixes RC-5Depends on T1

The spine of the roadmap. learning_centre/pipeline.py:826's step11_skill_evolution reads WHERE type = 'correction' AND source = 'user'. In production that signal is a person telling the engine it got something wrong. Kasukabe has no person, so skill evolution could not fire once no matter how long the run went, and this was invisible in the trace.

  • The world supplies the correction instead. Its signals are unambiguous and already happen: a tool call rejected for wrong location or insufficient funds, a negotiation that ended without settlement, a crop that spoiled, a build that failed inspection, a debt called in, a bankruptcy, a conviction. Emit each as a LearningSignal through SignalStore.write() from the sim seam, in the shape the pipeline already reads. The engine is unchanged; the world starts telling it when it was wrong.
  • Unify the two skill systems. world/ledger/action_costs.py's integer proficiency stays the money discount; the engine's distilled artifacts become the cognition discount. One skill, two effects, one number the agent can see in its disclosure.
  • Tag purposes so learning is affordable. broker/service.py:307 classifies by X-Kasukabe-Purpose and the engine sends that header nowhere, which is why the trace shows 100 percent cognition and zero background. Send it from the sim's herald adapter on every call.
Gate

Background share of calls is greater than zero and matches the number of sleep-onset edges. At least one skill artifact exists per agent by game-day 5. Compounding quantities 1 and 2 are met: median tokens per task type falls, and proficiency rises with repetition and lowers real cost.

T7 Navigation, observation and the missing primitives Next
Owner meDepends on T3 for the map

look_around, describe_place and list_places landed after round 1, because the town had 27 tools and no way to answer "where can I go". That work continues: an agent needs to query its own inventory and balances, the prices and stock where it stands, who is present, what tools this location permits, what a given action will cost before committing to it, who owes it and whom it owes, what rulesets bind it, and what has recently happened here. DESIGN.md requires all of it and none of it is implemented. Plus trade, an atomic two-sided swap distinct from buy and sell against a posted price.

Gate

An agent that has never been told a place exists can find it, walk there, learn what acting there costs, and act, using only tools.

T9 The voice lane After
Owner meDepends on T1, T3Scope operator voice

A seventh broker lane, separate from the six cognition and background lanes. It does not think about the world and never mutates it: the engine does the work through the tool registry as usual and the voice lane speaks the answer the engine produced, so Law 2 is untouched because the voice lane calls no tools. The shape is GPT-Live's delegation architecture with the world server in place of the application server and the September engine in place of GPT-5.5.

Round 2 ships operator voice: the President and God console gains a spoken channel. Agent voice — say and tell rendered as audio, with prosody and hesitation as measurable social signals — is its own track behind its own gate in Round 3, because it stacks cost and storm risk on top of T2. Mistral Large 3 is admitted for voice-lane non-cognition work only and may never serve an agent turn.

Gate

The operator holds a spoken exchange with a named agent during a live rung-1 run; the answer spoken is the answer the engine produced, and the trace shows the engine's tool calls behind it; no world state changes except through the registry; the voice lane's calls are tagged and separable from cognition in the trace.

T5 The tool economy: create, evolve, convey After
Owner SharanDepends on T3

world/tools/meta.py is genuinely well built — define_tool files a composition of primitives at the patent office for a fee, approve_patent wires it in, and the composite handler replays filed steps through the same gate-checked dispatch() path under the inventor's own agent id, so an invented tool is data and never a new code path. But validate_steps checks every step against the frozen primitive_names set and never against registry.tools, so an invented tool can never cite another invented tool and invention depth is capped at 1 by construction.

  • Lift depth to a bounded 3, with cycle detection at file time and the same gate-checked replay at call time. Every leaf stays a primitive, so "no new physics" remains true by construction — it becomes a depth bound rather than a flat ban.
  • Conveyance, all as tools: license_tool (revocable, priceable, term-bounded), sell_tool (ownership transfers, patent record follows), grant_tool_access and revoke (the business and organization ACL the trade-secret path assumes and never got), teach_tool (co-located, consensual, refusable, priceable, transferring at reduced proficiency), and inheritance through the existing estate path.
Gate

An agent invents a tool, files it, has it approved and calls it; a second files a depth-2 tool citing the first; a third acquires one by teaching, licence or sale and calls it; a business tool granted to an employee stops working the moment that employee is fired; a dead agent's tools reach an heir. Compounding quantity 3 is met.

T6 Rulesets After
Owner SharanDepends on T5

An organization or business registers a ruleset: a first-class object stating who may call which of its tools, on what terms, with what obligations, and what happens on breach. Membership conditions, fees and dues, revenue shares, price floors, wage floors, exclusivity, expulsion. Enforcement happens at dispatch time on the same gate-checked path every tool call already takes, so a breach is a world event that can reach the complaints desk and the courts.

This is what makes a guild, a cartel, a union, a priesthood or an employment contract expressible in the registry rather than only in conversation, and therefore measurable. The Town Charter is the government organization's ruleset and should be implemented as one: charter amendment and cartel rule-making become the same machinery, and the political and economic research read the same table. The A2A prototype's tighten-only policy engine — rules folded most-restrictive-wins over a lattice, evaluated on every request, never able to loosen — is the working reference for the enforcement half.

Gate

An organization registers a ruleset; a member's call is permitted under it and a non-member's is refused; a breach by a member produces a world event that reaches the complaints desk; the ruleset is amended by the organization's own procedure and the change takes effect on the next call.

T8 Context bound to the wallet After
Owner meFixes RC-4Depends on T1

One pinned thread per agent, never reset, accumulating every tick of an eight-day run. Compaction is real and does run, but compact_if_needed triggers against the model's context window, and Kimi's window is enormous relative to a $2 wallet, so history grew freely to 10,431 tokens per call and the compactor had no reason to fire. The economic constraint and the context constraint were never connected, and 132 of 250 agents thought themselves bankrupt with nothing in the loop noticing.

Give each agent a per-turn input-token budget derived from its balance and burn rate, make compaction trigger on that budget rather than the model's window, and publish the budget through the cost disclosure so thinking hard is a choice the agent makes knowingly. This is also the rung-3 economics argument: at a 4,000-token budget the same call volume costs about $15 a game-day instead of $26.75, so $500 buys roughly 30 game-days instead of 8.

Gate

p95 input tokens per call at or below 4,000 across a rung-2 run, with no agent bankrupt from context growth alone.

04 Exit, and what is still blocking

Round 2 exits when rung 1 is green twice on fresh seeds and then rung 2 is green once: five game-days with no agent bankrupt from harness defects, a complete trace, a console that can steer a live run, every institutional action reachable only through tools, and all four compounding quantities moving. It publishes an engineering note plus the round-1 negative result, and the existing 62,466-call dataset.

Blocking, and only you can clear it

  • Bedrock credentials and a dev spend cap. Everything proven so far ran in mock mode, which never constructs an engine session. The stripped transport layers are therefore entirely unexercised, and that is the largest unknown in this plan — it sits on the critical path for T1, since a character layer that cannot reach a model cannot be tested. make local-live is wired and waiting.
  • Sharan's split. The plan gives him T3 then T2 then T5 and T6, which is the whole world-server and tool-registry column. The alternative is splitting by layer rather than by track. Worth ten minutes at the start rather than discovering the seam later.
  • The Ville assets. Currently each developer sparse-checks them out by hand. A submodule or a bucket would be better, and it is a five-minute decision.

Risks I am carrying

  • T3 is the biggest single track in the round and it is on the critical path for four others. If it slips, T5, T6 and T9 slip with it.
  • Conversation storms once T2 lands. Mitigated by proving at rung 1 first, which now exists.
  • The engine core is fixed by Law 1. If T1 or T4 turns out to need a change under engine/src/ outside sim/, that is a finding about the engine and gets written up rather than patched around — and it would be a schedule event.
