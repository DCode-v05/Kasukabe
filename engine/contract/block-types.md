# Block-wire contract (generated)

> **Generated by `scripts/gen_block_contract.py` from the live code — do not edit by hand.**
> Run `python scripts/gen_block_contract.py` from the engine root to regenerate.
> `tests/test_block_contract.py` regenerates this in-memory and fails if it drifts.

The v2 `/execute` wire is **one** envelope, the `Block`, in **27 types**. The internal event dataclasses (`src/engine_core/events.py`) stay as they are on the internal bus; the fold to blocks happens only at the serialization boundary (`src/engine_core/blocks.py`). The SDK types every `block.payload` as a discriminated union over these types.

## The `Block` envelope

```python
@dataclass
class Block:
    type: str        # one of the types below
    payload: dict    # the folded event body (+ any stamped discriminator)
    thread_id: str = ""
    id: str = ""     # derived from the logical instance — NOT a fresh uuid (see id rule)
    ts: str = <iso8601 utc>
```

## The SSE frame

Each frame is serialized by `sse_frame(block, seq, cursor)`:

```
seq: {seq}
cursor: {cursor}
event: block
data: {"id": ..., "type": ..., "thread_id": ..., "ts": ..., "payload": {...}}

```

Every frame the engine emits carries both numbers, and they are not interchangeable. `seq` is the per-stream delivered-frame counter, bumped only for frames actually delivered — a block a stream's gates suppress does not advance it — so the SDK uses it and only it for gap detection. `cursor` is the per-thread buffer index of the block, and is the value the client passes back as `?after=` on `/replay` to resume where it left off.

The frame JSON has exactly these five keys: `id`, `type`, `thread_id`, `ts`, `payload`. There is **no `v` (version) field** — versioning is doc + conformance enforced; the `v` add stays the deferred, additive upgrade path. The SDK must not require a `v` field.

## Synthesized envelopes

`done` and `error` are not folded from events — they are synthesized at the `/execute` boundary. An in-stream error is emitted as an `error` block (`make_error_block`) followed by a terminal `done` block; the SDK raises the typed exception after the iterator drains.

### `done`

Synthesized from the last `ExecutionSummary` plus its `quota`:

```
{
  "status": "completed" | "awaiting" | "failed" | "cancelled",
  "num_turns": int,
  "cost_usd": float,
  "duration_ms": int,
  "quota": dict | null      // optional — citadel quota snapshot, present when known
}
```

### `error`

`EngineError.to_dict()["error"]`:

```
{
  "code": str,              // one of the ErrorCode values below
  "message": str,
  "retryable": bool,
  "details": dict           // optional — present only when non-empty
}
```

## Voice + media semantics

`voice` is speakable narration text, not audio: the model narrates inline, the engine streams it as append deltas on `voice:{turn_id}:{thread_id}` (no thread -> `voice:{turn_id}`), and the PRODUCT runs text-to-speech over the accumulated block text. The engine never synthesizes audio. Sub-agent narration arrives as its own block (`voice:{turn_id}-{agent_id}:{thread_id}`) so each speaker can be queued separately.

**TTS stop signal:** a terminal `done` or `error` block, or an interrupted stream, means the product must flush its TTS queue (stop speaking). No other stop channel exists on the wire.

**Replay / retries:** replayed voice deltas are history, not new speech — a product must not re-speak blocks it already delivered (track by `seq`/`cursor`). An engine-internal retry may restart a turn's narration on the same block id; the product keeps appending by id as usual.

`image` / `audio` / `video` blocks carry LINKS only, never bytes: payload is `{"title": str, "items": [{"url", "title", "caption", "mime"}]}` with one or more items of one kind (one block = one gallery = one id). Every URL was validated against the engine's per-thread provenance registry (it appeared in a tool result, a user input, or ingested media; http(s) only, no credentials, no private hosts) before emission — the product may render it directly.

## Fail-open rule (the SDK must mirror it)

`passes_gates()` returns `True` for any block `type` it does not recognize (`src/engine_core/blocks.py`). A new block type is therefore **never silently dropped** by the gate. The SDK must mirror this: an unknown `type` on the wire passes through to the consumer rather than being discarded.
